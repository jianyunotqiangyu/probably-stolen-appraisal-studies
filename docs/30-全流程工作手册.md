## 3. 日常开发回路（照这个顺序做）

### 3.1 改代码

`mod\AppraisalExpansion\src\*.cs`。加新的 Harmony 补丁前，**先确认方法属于哪个类**（P21/P22）。

### 3.2 改手册

手册 JSON 是**生成物**，不要手改：

```
python tools\build_knuckle_guide.py
```

它会重写 `mod\AppraisalExpansion\Books\knuckle_guide.json`。
改版式/文案 → 改这个脚本里的常量；改完记得跑一次，否则部署出去还是旧 JSON。

### 3.3 改素材

直接把 png 放进 `assets\paper\`（或 `assets\items\<物品ID>\<类别>\`）。
**文件名 = 运行时键名**，改名等于改键，JSON 里的 `sprite` 要跟着改。

### 3.4 构建 + 部署

```powershell
pwsh -NoProfile -File D:\DSH_workspace\mod-create\mod\AppraisalExpansion\scripts\deploy.ps1
```

它做四件事，缺一不可：

1. `build.ps1`：调 `csc.dll` 编译 → `build\AppraisalExpansion.dll`
2. `pack.ps1`：**先整体清空 `Textures\`**，再把 `assets\{items,paper,sounds}` 平铺成
   `Textures\Items\`、`Textures\Paper\`、`Sounds\`（跨类别查重名）
3. 整个替换游戏目录里的 `Textures\`、`Books\`
4. 复制 dll + manifest

**部署前会探测目标 dll 能否独占打开**，游戏开着就直接报错退出，一个文件都不动（P20）。

### 3.5 进游戏验证

1. 重启游戏 → Mod 页面**重新授权**（dll/manifest 变过就要授权，P5）；
2. 手册：F9 → Spawn → Knuckle Guide（或直接看柜台）；
3. 鉴定大图：F9 → Command → Knuckle Customer；
4. 看日志（见 §6）。

## 4. 美术流水线

### 4.1 尺寸约定

| 类别 | 尺寸 | 说明 |
|---|---|---|
| 物品图标 `icon` | 16 的整数倍（指节 16×32 = 1×2 格） | 点采样；**只按材质分模，不画状态/接口**（P11） |
| 鉴定大图底图 | 256×256 ×9（3 材质 × 3 状态） | 画布一致、内容对齐（当前 alpha 包围盒 71,54–185,202） |
| 接口叠层 | 256×256 ×2 | 只画接口标记，其余透明 |
| 手册背景 | **628×804** | 1:1 摆放，别用 314×402 让引擎放大（P24） |
| 手册按钮 | **28×30** | 同上；原版原图只有 14×15，放大 2 倍出图 |
| 手册插图 | **188×236** | 三列布局的最终显示尺寸 |

### 4.2 手册素材为什么必须 1:1

`PaperUI` 的坐标是**设计单位**。如果 `designWidth=314`、`width=628`，所有位图都会被放大 2 倍：

- `Textures\Paper\` 的图被 `ModLoader` 硬编码成 **Bilinear** → 放大就糊；
- `Textures\Items\` 的图是 **Point** → 放大出硬边（像素风）。

结论：**让设计空间 = 屏幕像素（628×804），素材按最终尺寸出图**，引擎不做任何重采样，双线性也不会糊。
（`Textures\Paper` 与 `Textures\Items` 的分工要保留，别为了“锐”把手册塞进 Items，P23）

### 4.3 拆原版素材（只在本机参考，不进包）

```
python tools\export_all_paper_sprites.py    # 导出 20 张纸质手册精灵到 reference\vanilla-paper\
```

UnityPy 只能读到 `Sprite` 级（`read_typetree` 对自定义 MonoBehaviour 常失败）；
原版纸张/按钮精灵都在 `sharedassets1.assets`，按名字直接找比按预制体逐层翻更快。

## 5. 手册（PaperUI）编写规范

### 5.1 骨架

```json
{
  "id": "knuckle_guide",              // 运行时 Id = "<模组ID>:<书id>"，例如 AppraisalExpansion:knuckle_guide
  "background": "paper_bg",
  "designWidth": 628, "designHeight": 804,
  "width": 628, "height": 804,        // 与 design 相等 = 1:1
  "posX": -450, "posY": 0,
  "chrome": [ /* 按钮与页码，坐标也在设计空间里 */ ],
  "pages": [ { "name": "...", "elements": [ ... ] } ]
}
```

### 5.2 文本元素的四个来源（优先级从高到低）

`ResolveText` 的实际顺序，**改文案前必须先知道这条链**：

1. `slot`（模板插槽）——**只能是纯字符串**，挂不了翻译（P29）
2. `loc`（本地化键）→ `ModHelper.GetLocalized(modId, key)`
3. `translations[当前语言]` → `LocHelper.GetCurrentLocaleCode()` **精确匹配**
4. `text`（兜底）

所以**要中英双语就别用 slot**，直接写元素 + `translations`。

### 5.3 字体与颜色

| 字段 | 作用 |
|---|---|
| `style` | 决定字体角色：header=Tektur / title=Noto Sans / section,body=Noto Serif / caption,label=Noto Sans Bold / page_number,handwritten=Caveat / stamp=Lubrifont |
| `fontSize` | > 0 时覆盖样式字号；**单位是设计单位**，设计空间翻倍它也要翻倍（P25） |
| `color` | `#RRGGBB`，`ColorUtility.TryParseHtmlString` 解析 |

当前手册取值：抬头 `header 22`、页标题 `title 26`、小标题 `label 18`、正文 `title 15`、图注 `caption 12`、页码 `page_number 30`；
深蓝 `#35526F`（标题类）、墨色 `#292234`（正文类）、浅灰 `#8b8375`（页码）。

### 5.4 国际化

```json
"translations": { "zh-Hans": "空间站贸易委员会", "zh": "空间站贸易委员会" }
```

Unity 简体中文的 locale code 是 **`zh-Hans`**；官方指南表格里写 `zh`。**两个都写**，谁匹配上用谁（P26）。

### 5.5 chrome 与页码

- 按钮：`{"type":"button","action":"close|zoom|flip_left|flip_right","sprite":"btn_close",...}`
- 页码：`{"type":"text","action":"page_indicator","style":"page_number",...}`
- 页码文本由原版 `PaperUI.ShowPage` 写入，**中文环境下是「第1/5页」**；模组 CSV 覆盖不了全局表，
  只能补丁改写（`src/PaperPageNumberPatch.cs`，逻辑见下）：

```csharp
[HarmonyPatch(typeof(PaperUI), "ShowPage")]
// Postfix 里：AccessTools.Field(PaperUI,"pageIndicators") → 逐个 Binding.text.text = "当前页/总页"
```

注意三点：
1. 类是 **`PaperUI`**，不是 `PaperUIPanel`（P21/P22）；
2. `pageIndicators` 是 private，`Binding`/`Binding.text` 是 public（`Assembly-CSharp` 159700/159703 附近）；
3. 只在本模组的书上生效：`__instance.Id.Contains("knuckle_guide")`。

### 5.6 内容规范（写手册文案时按这个来）

| 项 | 要求 |
|---|---|
| 文体 | 仿现实鉴定/估价文书：陈述句、条目化；不用口语、不写玩笑话、不给玩法提示 |
| 结构 | 总则 → 三要素分述 → 计价 → 示例；每页固定“判定方法 / 判定标准 / 背景说明 / 常见误判”四段式 |
| 背景 | 可写部件结构、材料成因、刻号工艺等描述性内容，**只描述，不指导玩家操作** |
| 结构 | **书名写在标题位**（`仿生指节鉴定指南`，每页相同）；小节标题写在正文里（`1.材料`、`2.品相`、`3.控制接口`）；示例用清单式（`基础：+85 / 镀金：+70 / … / 总计：170¢`），照原版写法 |
| 差分真实性 | **只写实现里存在的差分与判据**（当前 3×3×3 = 27 种）。写之前先看 `KnuckleItem.cs` 的权重表；没实现的机制（仿制镀层、重刻铭牌等）一个字都不写，背景描述也不得暗示不存在的分支 |
| 字数 | 每页中文 200–300 字：讲明白即可，不靠灌字撑版面 |
| 填充 | 每页内容底边落在 **y=604–684（75%–85%）**；不得越过 748，否则压到页码与翻页按钮 |
| 示例 | 至少两例；**一例只配一张整件图**（把 base + overlay 合成后就是该件的实际外观），不要拿三张轴图拼——那是“差分样本”，不是“一件东西” |
| 用词 | 同一档位在全册里只用一个名字（例：品相档是「无 / 磨损 / 受损」，就别在公式和示例里写成「完好」） |
| 估算填充 | 按 33 字/行、行高 1.38×字号 估算，写完后跑一次 `python tools/audit_books.py` 复核 |
| 终审 | 每次改完手册跑 `python tools/audit_books.py`：一次检查填充率、元素遮挡（按 alpha 包围盒与对齐后的实际字宽判定）、缺图、A12 禁用词，并列出三件物品的基准/底线数值供对照 |

> 排版禁区：正文区 172–740，底部 748–798 留给页码与翻页按钮。
> 原版手册原文（中文）已抽出到 `reference/vanilla-paper/book_hand_text_zh.txt`，写文案前先读它。

## 6. 排查手册

### 6.1 日志在哪

| 文件 | 内容 |
|---|---|
| `Player.log` | **全量**（含 `[ModLoader]`、`[PaperUI]`、模组自己打的日志）← 优先看这个 |
| `GameLog_时间戳.txt` | 过滤后的玩家版日志，**看不到** `[ModLoader]` 的行 |
| `mod-audit.log` | 加载器审计（能力声明、扫描结果） |

常用：

```bash
grep -a "AppraisalExpansion\|Paper sprite\|Item sprite\|PaperUI\|Harmony" Player.log
```

### 6.2 现象 → 原因 → 处理

| 现象 | 最可能的原因 | 处理 |
|---|---|---|
| 手册一点变化都没有 | 看的是**改动前的会话**（游戏没重启 / 没 `paper-reload`） | 重启；对日志时间戳与文件时间 |
| 按钮是蓝色方块 | `sprite` 键没解析到（null 回落蓝块） | 检查文件名与 JSON 键是否完全一致（含大小写）；看 `No sprite found for key` |
| 背景/按钮糊 | 设计空间 ≠ 屏幕像素，被引擎放大 + Bilinear | 按 §4.2 出 1:1 素材 |
| 手册文字是方块/空白 | 字体无该字形，或 `translations` 的 locale code 不匹配 | 看日志 `The character with Unicode value \uXXXX was not found`；改 locale code |
| 页码显示「第1/5页」 | 补丁没生效或目标类写错 | 看 `Harmony: N method(s) patched`；确认是 `PaperUI` |
| 启动弹 `ArgumentException: Undefined target method` | 补丁目标类/方法名不对 | 去 `Assembly-CSharp` 确认方法所属类（P21） |
| `deploy.ps1` 报“请先退出游戏” | dll 被游戏进程占用 | 退出游戏再部署（P20） |
| 编译报 `类型 TextMeshProUGUI 在未引用的程序集中` | 少了 `Unity.TextMeshPro.dll` 引用 | 加进 `build.ps1` 的 `$refs`（P28） |
| 改了一个字号，别的元素也变了 | 全局字符串替换误伤 | 用带上下文的精确替换（P27） |

### 7.2 本轮新增的坑（P22–P30，已同步进 00）

**P22 · `PaperUI` 与 `PaperUIPanel` 是两个类**
`ShowPage` / `CurrentPage` / `pageIndicators` 都在 **`PaperUI`**（`Assembly-CSharp` 159673 行起）；
`PaperUIPanel`（161153 行起）是面板层级。按字段名猜类名 → 补丁目标不存在 → 整个 Mod 加载失败。

**P23 · 同名键同时存在 Paper/Items 时，双线性那份赢**
`PaperAssets.FromMod` 先查 `PaperSprites` 再查 `Sprites`。旧 `Textures\Paper` 残留会和 `Textures\Items` 同名，
于是“点采样版本”被“双线性版本”顶掉。→ `pack.ps1` 每次先整体清空 `Textures\`。

**P24 · 糊的根因通常是“设计空间 ≠ 屏幕像素”**
`designWidth/Height` 与 `width/height` 不等 → 所有位图被放大；此时过滤模式决定糊/锯齿。
把两者设成相等（628×804）并按该尺寸出图，才是真正 1:1。

**P25 · `fontSize` 是设计单位，不是屏幕像素**
旧版设计空间 314 里 `fontSize 9`，屏幕上就是 18 px。改成 628 设计空间后 `fontSize 18` 仍是 18 px——
所以“把 9 改 18 却没变化”是正常的，想要更大得给更大的数。

**P26 · `translations` 按 locale code 精确匹配**
`LocHelper.GetCurrentLocaleCode()` 返回 Unity 的 `Locale.Identifier.Code`，简体中文是 `zh-Hans`；
指南里写的 `zh` 不一定命中。**两个键都写**。

**P27 · 全局字符串替换会误伤**
`"fontSize": 26` → `30` 这种替换，会把同值的**其它元素**（标题）一起改掉。
改单个元素时带上下文（前后键名/坐标）替换，改完 `grep` 复核。

**P28 · 用到 TMP 类型要给 csc 加引用**
`TextMeshProUGUI` 在 `Unity.TextMeshPro.dll` 里；`build.ps1` 的 `$refs` 少了它就编不过。

**P29 · 模板 slot 不支持 `translations`**
`slot` 命中时 `ResolveText` 直接返回 slot 字符串，翻译链被跳过。
要双语就**别用模板**，把 header/title/flow/body 直接写进页面。

**P30 · 原版本没有 `PaperAssetCatalog`**
`PaperAssets` 的第 3 步永远拿不到，`notebook_manual`、`guide_logo`、`paper_buttons_*` 这些原版键
在运行时**解析不出来**；要用只能导出成模组素材（`Textures\Paper`）自带。

## 10. 工作空间卫生（纪律 C1–C5）

对应 [01 §C](01-编写纪律对照表.md)。**每次收工做一遍**，成本很低，但能避免“下次打开发现一堆不知道能不能删的东西”。

### 10.1 体检脚本

```bash
python tools\workspace_check.py
```

只报告、不改文件。检查五项：

| 检查 | 判据 |
|---|---|
| 引用完整性 | 手册 JSON 里的 `background` / `sprite` 在 `assets/` 里是否都有对应文件 |
| 孤儿素材 | `assets/` 里有图片但 JSON 和 C# 都没引用（按前缀宽松匹配，防误报） |
| 临时文件 | `*.tmp *.bak *~ *.orig *.rej *.log`、`Thumbs.db`、`.DS_Store` |
| 生成物被手改 | `mod/…/Textures/` 与 `assets/` 里同名文件的 md5 是否一致 |
| 文档新鲜度 | `src/`+`Books/` 的最新修改时间是否比 `docs/` 新 0.5 小时以上 |

### 10.2 清理原则

| 对象 | 处理 |
|---|---|
| `build/`、`Textures/` | 可再生产物，随便删，`deploy.ps1` 会重建 |
| `assets/` 里的旧版本素材 | 移到 `_archive/`，别直接删（可能还要回滚） |
| `reference/` | 拆包研究成果，只读；**永远不进发布包** |
| 临时脚本 / dump | 用完即删，或放进 `_archive/` 并注明日期 |
| 部署中断后的游戏目录 | 必须重新跑一次 `deploy.ps1` 保证是一整套，不能半新半旧 |
