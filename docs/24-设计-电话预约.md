# 电话预约考官 · 设计 v1

> 名片上印的 `1717` 就是这条线的号码——致敬《彼方的她》。
> 台词里**不点站名、不点行会名**，只报「预约专线」：不确定的世界观名词不写。

## 一、玩法闭环

```text
双击名片 →（看到 1717）
   ↓
打开游戏内电话 → 拨 1717 → 接通行会接线员
   ↓
「预约考官上门」→ 挂断
   ↓
**次日开店时**，一位鉴定委员会成员到店，带三件待鉴定物品
```

## 二、接线方式（注册法）

用户 2026-11-17 决定：**用注册法**，不做 Harmony 拦截。理由是卸载后最多拨不通，不会崩。

| 环节 | 实现 |
|---|---|
| 号码 | `GuildPhone.Number = 1717L`（不用 0 开头：按 0 时 `currentNumber` 仍是 0，屏幕不显示前导零） |
| 号码簿 | `PlayerStore.PhoneClientDict[347] = StorePhoneClient{ dialogFuncId="AppraiserGuild", phoneState=Regular }` |
| 对话 | `PhoneClientList.DialogFuncs["AppraiserGuild"] = 客户 => BuildCallDialogue()`；**选项气泡显示的是下一个对话节点的正文**，所以每个选项单独建一格 |
| 通话界面 | **游戏原生** `DialoguePhoneUIManager`，不另做 UI |
| 补登时机 | `OnGameLoadedLate` + `OnShutterOpenedEarly`（与名片同一对钩子） |
| 到店时机 | 预约只写 `SetModDataBool("appraiser_visit_pending")`，**次日开店**由 `OnShutterOpenedEarly` 消费，当天不插队 |

## 三、卸载安全性（B9）

`PhoneClientDict` 是 ES3 序列化的存档字段，写进去就是改动存档。控制方式：

| 场景 | 结果 |
|---|---|
| 玩家**停用**模组 | `OnDisable` 里 `GuildPhone.Unregister()` 把 347 从号码簿删掉，并移除对话构造器 |
| 玩家**直接删掉**模组文件夹 | 存档里会留一行孤儿号码。拨过去：`GetCallDialog()` 返回 null，`StartPhoneDialog` 静默返回——**不崩溃、不报错**，停在拨号状态，按红色挂断键退出 |

这是已知且可接受的降级，写在这里备忘。若以后要更干净，可改成「前置补丁拦截 `HandleCall`」，即当初的方案 B。

## 四、考官上门

外观：原版**鉴定委员会成员**那一套——`SpriteDict.GetClerkSpriteName()` 的 clerk 精灵 + `name_appraiser_board_member` 的名字，`nonShootable = true`（和鉴定公告板上那位是同一个人格）。

`AppraiserVisit.Queue()`：

- 拼一个 `StoreClient`（`identifier=appraiserGuild`，名字取 `appraiser_name`，精灵随机拾荒者，阵营 `FACTION_LOWER_LEVEL`）；
- `clientIntent = APPRAISAL_SERVICE`，开场白 `appraiser_arrive`；
- 对话结束时把三件物品（指节 / 检测仪 / 终端 各一）放到柜台；
- `ModHelper.SetClientSource` 标记来源，`AddNextClient` 排队。

`[非规范实现]`：没有「立刻叫一位客人来」的原生 API，只能走原版 `CreateAppraisalRandom` 的同一条构造路径。风险与回退写在该文件头。

F9 的 `Knuckle Customer` 已改为**复用**这段逻辑，避免两处各写一遍。

## 六、晋升考核（2026-11-17 补）

### 原版路径已关闭

原版在进度满足后会由 `AppraisalRankHelper.HandlePromotionClient` 自动派人上门，玩家付钱即升级。
现在这条路径被前置补丁关掉（`PromotionVisitPatch`），改由电话预约触发。

### 预约门槛

拨号后先判 `AppraisalRankHelper.IsPromotionReady()`（进度 100%）：

| 情况 | 接线员回复 |
|---|---|
| 进度不足 | 您尚未满足晋升条件，还无法预约考试。当前进度 N% |
| 已预约未到店 | 已经替您约过了，考官明天会到店。 |
| 满足且未预约 | 记下了。考官明天开店时会到店…… |

### 考核与发证

考官到店 → 放三件待鉴定物品上柜台 → 玩家逐件估价：

- 每件按**游戏自己的估价精度**判定（`AppraisalServiceHelper.GetEstimatePrecision` 1..5）；
- `AppraisalRankHelper.IsGradeAccepted(precision)` 为真算这件合格；
- **考核期间不计鉴定费**：`AppraisalServiceHelper.GiveAppraisalFee` 整段跳过（不加钱、不出鉴定纸条），收入只有 150¢ 考试费；
- **三件里过两件**才算通过；
- 通过才调 `AppraisalRankHelper.Promote()`（内含换证书 + 发新手册）；不通过不发证，只提示下次再约。

实现方式：Postfix 旁听 `AppraisalServiceHelper.OnEstimate(GameItem, int)`，
按 `currentClientInstance` 的 identifier 认人（`appraiserGuild`），数到三件结算。
### 结算对话

| 节点 | 台词 |
|---|---|
| 结果 | 通过「让我看看……很好，你通过了。」／未通过「很遗憾，你未能通过考试，再多练练吧。」 |
| 选项 | 「缴费 150¢。」／「这次先不缴。」 |
| 缴费·通过 | 扣 150¢ → Promote →「这是你的证书。」 |
| 缴费·未通过 | 扣 150¢ → 不发证 →「费用收下了。证书这次不能给你。」 |
| 不缴 | 「行，记录我先留着。想拿证就再来一次。」→ 不发证 |

钱不够：**不单列台词**，照搬原版晋升的做法——AddChoice 的第 6 个参数 choiceEnabled 传 () => playerCash >= 150，选项直接变灰点不动。

延迟：结算挂在 `StoreClient.allDoneDialogue` 上（原版 29080–29099 行：最后一件估完时，游戏会把 allDoneDialogue 接在「估价接受」台词之后）。我们的 Postfix 在那一刻把结果与收费填进同一个 Dialogue 对象，玩家点掉接受台词就进结算——不抢屏、也不需要另挂钩子。

冷却：exam_last_day 记在模组数据里，CooldownActive() 用 StoreStation.dayCounter 判当天不能再约。

## 七、快捷拨号与调试

### 快捷拨号

原版电话簿只列 `ShownInPhoneBook()` 为真的联系人，而它要求 `dialedBefore == true`（拨过一次才会出现）。
我们照原版规矩：注册时 `dialedBefore = false`，**第一次手输 1717 接通后**由游戏的 `StartPhoneDialog` 置真，
从那以后电话簿里就有这条联系人，可一键拨通（`ContactElement.OnQuickDial` → `PhoneUIManager.AutoCall`）。

### F9 调试按钮（Command 分类）

| 按钮 | 作用 |
|---|---|
| `Examiner Now` | 立刻把考官排进队列（跳过预约与次日等待） |
| `Examiner Tomorrow` | 只写预约标记，模拟电话预约，次日开店到店 |
| `Exam Ready 100%` | 把晋升进度直接拉满，方便测「满足条件才能预约」 |
| `Exam Clear Cooldown` | 清掉「考试当天不能再约」的冷却 |
| `Exam Cert Now` | 直接 `AppraiseRankHelper.Promote()`，验证发证与手册补发 |

测试顺序建议：`Exam Ready 100%` → 拨 1717 预约 → `Examiner Now` → 估三件 → 点掉回应 → 结算对话。
