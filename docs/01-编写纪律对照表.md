## C. 工程卫生（自我维护）

| # | 纪律 | 做法 |
|---|---|---|
| C1 | **定时清理工作空间** | 每次收工（至少每天一次）清一遍：删临时脚本 / 临时 png / 调试 dump；过期素材移进 `_archive/`，不要散落在 `assets/`、`src/`；`build/` 与 `Textures/` 是可再生产物，随时可删 |
| C2 | **文档状态跟着代码走** | 改完核心逻辑 / 版式 / 素材规格后，同步更新：`00` §1 状态表与坑表、`30` 对应章节、本表的状态列；文档顶部“最近更新”日期要改 |
| C3 | **源素材唯一来源是 `assets/`** | `mod/…/Textures/` 是生成物，禁止手改（下次 pack 会覆盖）；`reference/` 只读，不进发布包 |
| C4 | **定期体检** | 跑 `python tools\workspace_check.py`：手册引用的图是否缺失、`assets/` 里有没有没人引用的孤儿图、有没有临时/重复文件、文档是不是落后于代码 |
| C5 | **不留半成品** | 部署中断（游戏占用 / 编译失败）后必须确认游戏目录是完整的一套，不能留“新 dll + 旧资源”的混合状态 |

## E. 超规范实现的标注规则

用户要求：**凡超出官方指南覆盖范围的地方，必须在代码里就地标注**，便于 debug 与后续迁移。

统一格式（C# 注释，紧跟被标注的成员）：

```csharp
// [非规范实现] <做了什么>
// 依据：<指南的哪一条 / 哪一节说明不支持>
// 风险：<游戏更新后可能怎么坏>
// 回退：<如果它坏了，改用哪条规范路径>
```

| 标记 | 含义 |
|---|---|
| `[非规范实现]` | 指南未覆盖，靠 Harmony/内部字段实现；允许存在，但必须标注 |
| `[待迁移]` | 已有可行规范路径，当前实现只是过渡 |
| `[待确认]` | 依赖游戏内实测结论，尚未验证 |

## F. 命名与致敬（用户 2026-11-17 定）

> **数字、地名、机构名可以自由发挥，但必须有依据**——致敬某个游戏、小说、电影、现实典故都行。
> 不允许"随手起一个听着顺耳的"。

规则：

1. 新起一个玩家能看见的专有名词（号码 / 地名 / 机构 / 套装名）时，**先想清楚向谁致敬**；
2. 在下方台账登记：名字 → 依据 → 用在哪；
3. 找不到合适依据时，**宁可不点名**（写成"预约专线""接线员"这种通名），也不要编一个空心的专有名词。
