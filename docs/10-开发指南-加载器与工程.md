# 深空当铺（Probably Stolen）Mod 开发指南

> 适用：正式版（Steam AppID 4348910，本机 GameLog_*.txt 中 ModLoader 审计为 `game 0.46D`，ModLoader 100-Rev1 起）
> 本文只讲"怎么做"，不涉及具体玩法设计。

---

## 一、先纠正一个最常见的坑

网上（游侠、3DM、Nexus、部分 B 站教程）大量教程写的是：

- 装 MelonLoader
- 复制 `EZapi.dll`
- 把 dll 丢进 `Mods`

那是 **Demo 版（AppID 4349200）** 的做法。正式版已经换成**游戏内置的原生 ModLoader**：

- 不需要安装 MelonLoader；
- `0Harmony.dll` 由游戏自带（在 `Probably Stolen_Data\Managed` 里）；
- Mod 由游戏主菜单的 Mod 页面（中文界面可能叫「改装件」）管理：启用、排序、信任确认；
- 启用/禁用需要重启游戏（加载器里有 `RestartRequired` 标记）。

开源证据：`Codesoulme/shenkongdangpuMOD` 的入口注释写着
"The formal game has no MelonLoader"，并且它的 `MelonLogger` 只是自己写的兼容壳，最终转发到 `Debug.Log`。

## 二、Mod 到底是什么

一个 Mod = **一个 .NET 类库 DLL + 一个 manifest.xml**，放进：

```
<游戏根目录>\Mods\<ModID>\
    ├── manifest.xml
    ├── YourMod.dll
    └── preview.png        （可选，Mod 页面预览图）
```

游戏启动时，`ModLoader` 会：

1. 扫描 `Mods` 下每个文件夹，解析 `manifest.xml`；
2. 校验 ID、游戏版本、依赖（`Prerequisites`）；
3. 用 Cecil 扫描 DLL 的 IL，推断它**实际需要的能力**，与清单里声明的 `Capabilities` 比对；
4. 玩家批准后写入信任记录（清单哈希 + 文件哈希 + 检测结果）；
5. 加载程序集，找到实现 `IMod` 的类，调用 `Init(manifest)`，再按启用状态调用 `OnEnable()`；
6. 对程序集执行 Harmony 的 `PatchAll`（0Harmony 由游戏提供）。

> 信任记录意味着：你**改了 DLL 或 manifest 的任何一个字节**，玩家都要重新批准一次。这是防篡改设计，不是 bug。

## 三、IMod 接口（就三个方法）

`IMod` 和 `ModManifest` 都在 `Assembly-CSharp.dll` 的**全局命名空间**里（没有 namespace），直接写就行：

```csharp
using UnityEngine;

public sealed class MyMod : IMod
{
    public void Init(ModManifest manifest)
    {
        // 清单解析完成后调用一次：读 ID / 版本 / 作者
    }

    public void OnEnable()
    {
        // 玩家启用时调用；禁用再启用会再次调用
    }

    public void OnDisable()
    {
        // 关闭 Mod 或退出游戏时调用
    }
}
```

实测签名（从 `Assembly-CSharp.dll` 元数据解出）：

```
void Init(ModManifest)
void OnEnable()
void OnDisable()
```

需要每帧逻辑时，自己在 `OnEnable` 里挂一个 `MonoBehaviour` 驱动：

```csharp
var host = new GameObject("MyMod.Driver");
Object.DontDestroyOnLoad(host);
host.AddComponent<MyDriver>();   // MyDriver.Update() 里做轮询
```

## 四、manifest.xml

字段与 `ModManifest` 类一一对应：

```xml
<?xml version="1.0" encoding="utf-8"?>
<ModManifest>
  <ID>AppraisalExpansion</ID>
  <Name>鉴定拓展</Name>
  <Author>你的名字</Author>
  <ModVersion>0.1.0</ModVersion>
  <Description><![CDATA[
### 鉴定拓展
Mod 页面里显示的说明，支持 Markdown。
]]></Description>
  <GameVersions>
    <Version>0.46D</Version>
  </GameVersions>
  <Prerequisites>
    <!-- 可选：依赖的其他 Mod ID -->
  </Prerequisites>
  <Assemblies>
    <Assembly>AppraisalExpansion.dll</Assembly>
  </Assemblies>
  <Capabilities />
</ModManifest>
```

> 版本号：Steam 商店/新闻里显示 `1.0.0.12`，但 ModLoader 审计日志里是 `game 0.46D`；工坊里可用的 Mod 清单写的也是 `0.46D`。`<GameVersions>` 以 ModLoader 审计为准。

### 能力（Capabilities）

`ModCapability` 枚举：

| 枚举值 | XML 写法 | 什么时候需要 |
|---|---|---|
| `Files` | `files` | 读写磁盘文件 |
| `Network` | `network` | 联网请求 |
| `Process` | `process` | 启动/操作外部进程 |
| `DynamicCode` | `dynamic-code` | **已弃用**（2026-12-10 起拒绝）：`Assembly.Load`/`Reflection.Emit` 等运行时加载或生成代码。**Harmony 打补丁不需要它** |
| `Native` | `native` | **已弃用**：P/Invoke 原生库 |
| `ReflectionExternal` | `reflection-external` | **已弃用**：扫描器读不出的反射（拼接成员名、`someObj.GetType().GetField` 等）。`typeof(游戏类型).GetField("x")` 属游戏类型字面反射，**免费** |
| `Steam` | `steam` | 调用 Steam 接口 |
| `SteamAuth` | `steam-auth` | Steam 身份/票据 |

> **重要更正**：Harmony 补丁、钩子、物品/贴图/手册/自定义 UI，都**不需要任何能力**。本工程 `manifest.xml` 因此是 `<Capabilities />`。
> 旧版本表格把 `dynamic-code` 写成"Harmony 打补丁"，是错的，来自早期未核对指南的推测。

- **少声明**：扫描器检测到未声明能力 → 加载被拒。
- **多声明**：一般能过，但玩家看到的风险提示会变多。
- 只是读游戏对象、不打补丁、不反射私有字段的 Mod，可以一个能力都不声明。

> 能力名以清单里实际解析为准；上表依据开源 Mod 的工作清单与 `ModCapability` 枚举。改完后进游戏看 Mod 页面的能力提示即可验证。

## 五、工程与编译

### csproj 要点

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>netstandard2.1</TargetFramework>
    <PlatformTarget>x64</PlatformTarget>
    <AssemblyName>AppraisalExpansion</AssemblyName>
    <CopyLocalLockFileAssemblies>false</CopyLocalLockFileAssemblies>
    <GameDir Condition="'$(GameDir)' == ''">D:\SteamLibrary\steamapps\common\Probably Stolen</GameDir>
    <ManagedDir>$(GameDir)\Probably Stolen_Data\Managed</ManagedDir>
  </PropertyGroup>
  <ItemGroup>
    <Reference Include="Assembly-CSharp"><HintPath>$(ManagedDir)\Assembly-CSharp.dll</HintPath><Private>false</Private></Reference>
    <Reference Include="0Harmony"><HintPath>$(ManagedDir)\0Harmony.dll</HintPath><Private>false</Private></Reference>
    <Reference Include="UnityEngine.CoreModule"><HintPath>$(ManagedDir)\UnityEngine.CoreModule.dll</HintPath><Private>false</Private></Reference>
  </ItemGroup>
</Project>
```

需要 UI、TMP、Newtonsoft、Steamworks 时，继续按同样方式引用 `Managed` 下的 dll。
`Private=false` 很重要：游戏自带的程序集不要复制进 Mod 目录，否则会加载冲突。

### 环境

- 需要 **.NET SDK 8**（本机目前只有 6/8 运行时，没有 SDK；模板已用 Roslyn 命令行验证可编译）。
- 编译：`dotnet build -c Release`
- 部署：`pwsh -File .\scripts\deploy.ps1`

## 六、改游戏的三种手段

### 1. Harmony 补丁（主力）

```csharp
[HarmonyPatch(typeof(PlayerStore), nameof(PlayerStore.EndNight))]
internal static class EndNightPatch
{
    private static void Postfix()
    {
        // 原方法执行后
    }
}
```

- `Prefix` 可跳过原逻辑（返回 false）；
- `Postfix` 改返回值（`ref __result`）；
- `Transpiler` 改 IL（最脆弱，版本更新最容易坏）。
- 加载器统一 `PatchAll`，一般不需要自己 `new Harmony(...)`；若补丁未生效，可在 `Init` 里兜底手动 `PatchAll`。

### 2. 反射读写私有字段

游戏大量状态是私有字段。开源 Mod 的做法是集中到一个 `FormalGameAccess` 类里：

```csharp
const BindingFlags F = BindingFlags.Instance | BindingFlags.Public | BindingFlags.NonPublic;
var field = typeof(StoreClient).GetField("somePrivateField", F);
```

把版本差异收敛在一处，升级时只改这个文件。
反射访问外部程序集私有成员 → 声明 `reflection-external`。

### 3. 游戏自带的注册表 / 目录类

这是最"官方"的扩展方式：游戏内部很多内容用 Registry/Directory 管理，Mod 可以直接注册新条目（见下一节鉴定）。

## 七、鉴定系统的钩子地图（重点）

> 以下成员均在本机 0.46D 的 `Assembly-CSharp.dll` 中实测存在；游戏更新后可能改名，升级前用 ILSpy 复核。

### 内容扩展（加新的可鉴定物品类型）

`AppraisalItemType` 是一个**用委托描述规则**的类：

| 字段 | 类型 | 作用 |
|---|---|---|
| `id` | string | 类型 ID |
| `unlockRank` | int | 解锁所需鉴定等级 |
| `createRandom` | `Func<GameItem>` | 随机生成一件该类型物品 |
| `isType` | `Func<GameItem,bool>` | 判断某物品是否属于该类型 |
| `getCorrectValue` | `Func<GameItem,int>` | 计算该物品的"正确答案"估价 |
| `itemId` | string | 对应物品 ID |
| `guideItemId` | string | 图鉴/指南物品 ID |
| `displayName` | `Func<string>` | 显示名 |
| `source` | string | 来源标记（原版/Mod） |

`AppraisalItemRegistry`（静态注册表）：

```
Register(AppraisalItemType)      // 注册新类型
Get(string)                      // 按 id 取
Find(GameItem)                   // 按物品反查类型
RemoveAll(string)                // 按来源批量移除（卸载/禁用时清理）
GetAll() / GetUnlocked(int) / GetPool(int)
GetLowestRankType() / GetNewestUnlockRank(int)
CanBlock(type, rank) / IsBlocked(type, rank) / IsLastAllowed(...)
```

注册示例（结构示意，具体物品创建按你的方案）：

```csharp
var type = new AppraisalItemType
{
    id = "appraisal.mod.pocketwatch",
    unlockRank = 0,
    itemId = "mod_pocketwatch",
    source = "AppraisalExpansion",
    displayName = () => "旧怀表",
    isType = item => item != null && item.id == "mod_pocketwatch",
    getCorrectValue = item => 120,
    createRandom = () => /* 返回一件 GameItem */
};
AppraisalItemRegistry.Register(type);
```

> 注意：`OnDisable` 里用 `RemoveAll("AppraisalExpansion")` 清理，避免禁用后注册表里留下悬空条目。

### 流程

| 类 | 关键成员 | 可挂的点 |
|---|---|---|
| `AppraisalHelper` | `InitAppraisalItem(GameItem,int)`、`SetDefaultAppraisalValue`、`GetCorrectBaseValue`、`CreateAppraisalTooltip`、`GetStartNegotiationDialog` | 初始化、默认值、正确基价、提示条、开场对话 |
| `AppraisalServiceHelper` | `IsAppraisalAcceptable`、`GetEstimatePrecision`、`GiveAppraisalFee`、`OnEstimate`、`GetQualityName`、`GetTooHighDialog`/`GetTooLowDialog`/`GetPatienceRunOutDialog` | 估价是否被接受、精度、服务费结算、玩家估价提交 |
| `AppraisalRankHelper` | `GetFeePercent`、`GetBaseFee`、`GetThreshold`、`AddProgress`、`OnEstimateAccepted`/`OnEstimateRefused`/`OnCustomerWalkout`、`Promote`、`GetPromotionCost`、证书相关 | 等级、经验、晋升、费率、证书 |
| `InspectionUIManager` | `OnInspectItem`、`UpdateAppraisalPanel`、`OnAppraisalServiceEstimated`、`ChangeAppraisalServicePrice`、`OnConfront*` | 鉴定界面、估价面板、服务定价、对质流程 |
| `InspectableHelper` | `InitInspectableItem`、`IsConfrontCorrect`、`OnConfrontSuccess` | 真伪判定与对质 |

### 事件（做统计/联动时用）

`AppraisalSentEvent`（`ItemId/ActualValue/SentValue/Day/RunNumber/...`）、
`OnInspectedEvent`（检查结果）、
`AppraisalGuildInteractionEvent`（鉴定公会交互）、
`InspectorArrivedEvent`、`InspectionBribeEvent`。

## 八、调试

- 日志：`%USERPROFILE%\AppData\LocalLow\Questing Goose Studio\Probably Stolen\GameLog_*.txt`
  用 `Debug.Log("[MyMod] ...")` 打标记，方便过滤。
- 游戏内调试控制台（QFSW.QC）带 Mod 相关命令：
  - `mod-scan`：扫描 Mod 程序集，打印它"实际需要"的能力与命中项；
  - `mod-trust`：查看本机信任记录（哈希、能力、批准时间）。
  这两个命令对排查"为什么被拒绝加载"非常有用。
- 反编译工具：dnSpy / ILSpy 打开 `Probably Stolen_Data\Managed\Assembly-CSharp.dll`，
  直接搜类名（`Appraisal`、`Inspection`、`StoreClient`、`PlayerStore`）。

## 十、版本兼容

- 游戏更新很频繁（0.46D 之后仍有连续补丁），私有字段、方法签名、枚举都可能变；
- 建议：
  1. `GameVersions` 只写你实测过的版本；
  2. 所有反射访问集中到一个兼容层；
  3. Patch 用 `nameof()` + 明确参数类型，别用字符串硬编码；
  4. 每次游戏更新后跑一遍 `mod-scan` 与核心流程回归。
